# Лабораторная работа 4
# Полиморфизм и наследование

## Цель работы

Реализовать иерархию фигур с абстрактным базовым классом и коллекцию, которая хранит объекты разных типов. Использовать виртуальные функции, `dynamic_cast` и ручное управление памятью.

Вариант 3: 3D-тела. Основная характеристика фигуры `metric()` возвращает объём.

## Классы и операции

| Класс | Поля | Объём | Свой метод |
| --- | --- | --- | --- |
| `Sphere` | радиус `r` | 4πr³ / 3 | `radius()` |
| `Cube` | ребро `a` | a³ | `edge()` |
| `Cone` | радиус `r`, высота `h` | πr²h / 3 | `slantHeight()` |

Размеры должны быть конечными и неотрицательными. Конструкторы без параметров создают фигуры с нулевыми размерами.

`Figure` задаёт общий интерфейс: вычисление объёма, ввод, вывод и создание копии. Эти методы виртуальные, поэтому вызывается реализация нужной фигуры. Деструктор тоже виртуальный, чтобы фигуру можно было корректно удалить через `Figure*`. Методы, которые не меняют объект, объявлены с `const`.

Операторы `<<` и `>>` вызывают виртуальные методы вывода и ввода. `operator double` возвращает объём, а `operator==` сравнивает объёмы с точностью `1e-6`.

`FigureCollection` хранит указатели на фигуры в собственном динамическом массиве. После успешного `add()` коллекция владеет переданной фигурой и удаляет её при вызове `remove()` или разрушении коллекции. Один указатель нельзя добавлять повторно или удалять вручную после успешного добавления. При копировании `clone()` создаёт отдельные объекты нужных типов; при перемещении владение передаётся без копирования. Для коллекции реализовано правило пяти.

Основные методы коллекции: `add()`, `remove()`, `size()`, `empty()`, `totalMetric()` и доступ к элементам через `operator[]`. В `main.cpp` показаны обход коллекции и вызов методов конкретных фигур через `dynamic_cast`.

## Ввод и вывод

Вводятся только размеры: для сферы `r`, для куба `a`, для конуса `r h`. Например, `3 4` задаёт конус с радиусом 3 и высотой 4. При некорректном вводе поток переходит в состояние ошибки, а размеры фигуры не меняются.

Вывод содержит имя класса, размеры и объём, например `Cube: a=3 volume=27`. Сейчас формат вывода не совпадает с форматом ввода: строку вывода нельзя целиком передать обратно в `operator>>`.

## Используемые инструменты

- C++20
- CMake 3.20+
- Google Test 1.14.0

## Сборка и запуск тестов

Команды выполняются из корня проекта. При первой сборке тестов CMake скачивает Google Test из GitHub.

```bash
cmake -S . -B build
cmake --build build --config Debug
ctest --test-dir build -C Debug --output-on-failure
```

Для запуска примера в Linux используется `./build/oop_lab_4`. В Windows путь к исполняемому файлу зависит от выбранного генератора CMake.

## Проверка памяти

Для Linux или Ubuntu в WSL с AddressSanitizer и UndefinedBehaviorSanitizer:

```bash
cmake -S . -B build-asan -DCMAKE_BUILD_TYPE=Debug -DCMAKE_CXX_FLAGS="-fsanitize=address,undefined -g -fno-omit-frame-pointer"
cmake --build build-asan
ASAN_OPTIONS=detect_leaks=1 ./build-asan/run_tests
```
